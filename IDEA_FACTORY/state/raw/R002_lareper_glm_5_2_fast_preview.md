IDEA: METHOD — 10-секундный blur-тест первого экрана
KNOB: METHOD: Открыть index.html в браузере, сделать скриншот, размыть его (CSS filter: blur(6px) в devtools на body или фото-редактором), показать 3 людям на 5 секунд и спросить: «что продают, за сколько, что сделать дальше?». Если ≥2 из 3 не называют «лендинг за 2 дня» и CTA — h1/подзаголовок/CTA слабые.
EFFECT: Быстрая проверка ясности оффера без правок кода; выявляет, читается ли главный экран за секунды.
RISK: Субъективность малой выборки — выводы могут быть шумными.
ROLLBACK: Метод не меняет файл; скриншот и заметки просто удалить.
VERIFY: Весь тест занимает ~10 минут: скриншот + 3 респондента + фиксация ответов.
PRIORITY: 1 — самый дешёвый способ валидации первого экрана до любых правок.

IDEA: METHOD — A/B заголовка h1 на копиях файла
KNOB: METHOD: Скопировать index.html в variant-b.html, заменить в h1 только формулировку (например, вынести цену/срок в начало), открыть обе версии в двух вкладках, замерить глазами по чек-листу: длина ≤60 символов, есть «за 2 дня», есть город/выгода, читается с телефона. Сравнить снапшоты в devtools (Lighthouse → SEO/Performance) — фиксировать баллы до/после.
EFFECT: Позволяет выбрать сильнейший заголовок до изменения оригинала; Lighthouse даёт объективные баллы для сравнения.
RISK: Без реального трафика сравнение только экспертное, не поведенческое.
ROLLBACK: Оригинал index.html не тронут; удалить variant-b.html.
VERIFY: 5 минут: две копии + два прогона Lighthouse + чек-лист из 4 пунктов.
PRIORITY: 2 — даёт данные, но без живого трафика это эвристика.

IDEA: METHOD — аудит клавиатурной навигации за 3 минуты
KNOB: METHOD: Открыть index.html, нажать Tab от верха страницы и пройти все интерактивные элементы (CTA-ссылки). Проверить: виден ли focus-стиль на каждом, логичен ли порядок, нет ли «ловушек». Параллельно в devtools → Rendering → «Emulate vision deficiencies» включить blurred vision для проверки контраста CTA. Записать список элементов без видимого focus.
EFFECT: Находит недоступные CTA — потерянные заявки с клавиатуры и с мобильных (focus-стили коррелируют с тап-отзывчивостью).
RISK: Ручной проход может пропустить edge-cases (например, поведение при скринридере).
ROLLBACK: Метод не меняет файл; только заметки.
VERIFY: 3–5 минут на полный проход Tab + скриншоты проблемных мест.
PRIORITY: 1 — при 0 форм/кнопок CTA через ссылки — критичный путь конверсии, а проверка почти бесплатна.
