### Замена 1. FAQ с персистентным состоянием («persistent‑faq‑details»)

IDEA: Persistent FAQ details with localStorage  
KNOB: Заменить текущие FAQ‑блоки на `<details class="faq-item">` + `<summary>` и добавить скрипт, который сохраняет `open`‑состояние каждого `<details>` в `localStorage` (ключ `faq-open-<id>`). При загрузке страницы скрипт читает хранилище и открывает нужные пункты.  
EFFECT: Пользователи видят уже раскрытые ответы при повторных визитах → повышается удобство, снижается количество кликов → рост конверсии на CTA в конце FAQ.  
RISK: Требует небольшого JavaScript‑кода; если пользователь отключит JS, FAQ будет работать в базовом режиме без сохранения.  
ROLLBACK: `git checkout -- index.html` (или удалить добавленный скрипт и вернуть оригинальные HTML‑блоки).  
VERIFY: Открыть страницу, раскрыть 2‑3 пункта FAQ, перезагрузить – они должны оставаться открытыми; проверить в режиме инкогнито (JS‑вкл.) и без JS (JS‑выкл.) – в последнем случае FAQ просто работает без сохранения.  
PRIORITY: 1 – мелкое изменение, но существенное влияние на UX и показатель “time on page”.

### Замена 2. Улучшенная клавиатурная доступность («focus‑visible‑outline»)

IDEA: Add consistent focus-visible outline for all interactive elements  
KNOB: В CSS добавить правило  

```css
/* SAFE CSS */
:focus-visible {
  outline: 3px solid var(--blue);
  outline-offset: 2px;
  border-radius: 4px;
}
a:focus-visible,
button:focus-visible,
[role="button"]:focus-visible,
.nav-links a:focus-visible,
.btn-primary:focus-visible {
  outline: 3px solid var(--blue);
}
```

и обеспечить, что все ссылки‑CTA и навигационные ссылки используют `tabindex="0"` (если они не‑интерактивные по умолчанию).  
EFFECT: Явный визуальный индикатор фокуса улучшает доступность, повышает доверие пользователей с ограниченными возможностями и соответствует WCAG 2.1 AA; это также положительно воспринимается поисковыми системами (SEO‑фактор “accessibility”).  
RISK: Минимальный риск – возможные конфликты с уже существующими `outline:none` в некоторых стилях; решается добавлением `!important` только при необходимости.  
ROLLBACK: Удалить добавленный блок CSS и вернуть прежний файл (`git checkout -- index.html`).  
VERIFY: В браузере включить клавиатурную навигацию (Tab), пройтись по всем интерактивным элементам – каждый должен получать синий контур; проверить в Chrome DevTools → Accessibility → “Focus order”.  
PRIORITY: 2 – низкая стоимость реализации, но критичный для соответствия a11y‑стандартам и повышения конверсии через доверие.
