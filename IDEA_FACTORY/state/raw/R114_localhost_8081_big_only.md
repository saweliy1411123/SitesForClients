IDEA: CTA‑текст‑вариант через URL‑параметр  
KNOB: METHOD: 1) Открыть `index.html` в Chrome, открыть DevTools → Console. 2) Выполнить скрипт, который читает параметр `?cta=alt` и, если он присутствует, меняет `textContent` всех ссылок‑CTA с классом `.btn-primary` на альтернативный копирайт (например, «Получить бесплатный демо‑макет»). 3) Сохранить скрипт в консоли для быстрой повторяемости.  
EFFECT: Позволит быстро сравнить, какой вариант текста CTA генерирует больше кликов (можно использовать уже реализованный «CTA Click Logger via Console» I‑00618 для измерения).  
RISK: Изменения действуют только в текущей сессии браузера; при перезагрузке вернётся оригинал, поэтому результаты могут быть недостоверны без постоянного логгера.  
ROLLBACK: Перезагрузить страницу (Ctrl + R) — все изменения исчезнут.  
VERIFY: Открыть `index.html?cta=alt`, убедиться, что текст всех `.btn-primary` изменён, кликнуть несколько раз и проверить вывод в консоли от логгера (I‑00618).  
PRIORITY: 2 – быстрый 2‑минутный тест, высокий потенциал повышения CTR без изменения кода.

IDEA: Аудит порядка фокус‑элементов клавиатурой  
KNOB: METHOD: В консоли выполнить скрипт, который перебирает все интерактивные элементы (`a[href], button, input, textarea, select, [tabindex]:not([tabindex="-1"])`), сохраняет их в массив и выводит последовательность `tag → text/aria-label → tabindex`. При каждом событии `focus` добавить запись в массив `focusLog`. После обхода (например, через `setTimeout` 2000 ms) вывести `focusLog` в консоль.  
EFFECT: Выявит проблемы с таб‑путём (пропущенные ссылки, нелогичный порядок), улучшит доступность и потенциально повысит конверсию за счёт более удобной навигации.  
RISK: Скрипт только читает DOM, не меняет его; риск минимален, но может конфликтовать с уже существующими `focus`‑обработчиками.  
ROLLBACK: Нет изменений в DOM; закрыть вкладку или перезагрузить страницу.  
VERIFY: Запустить скрипт, перемещать фокус клавишей `Tab`, убедиться, что в `focusLog` отображается ожидаемый порядок и нет «потерянных» элементов.  
PRIORITY: 2 – важный для a11y, лёгкий в реализации, быстро проверяется.

IDEA: Тест переключения основной цветовой палитры через query‑param  
KNOB: METHOD: В консоли добавить короткий скрипт, который проверяет `new URLSearchParams(location.search).has('theme=alt')`. Если параметр найден, изменить CSS‑переменную `--blue` (и при необходимости `--grad`) на альтернативный оттенок (например, `#ff6b6b`). Сделать это через `document.documentElement.style.setProperty('--blue', '#ff6b6b')`.  
EFFECT: Быстрая проверка, как изменение фирменного цвета влияет на восприятие, время на странице и CTR CTA (можно совместить с логгером кликов).  
RISK: Временное изменение стилей может конфликтовать с анимациями, но не сохраняется после перезагрузки.  
ROLLBACK: Перезагрузить страницу — оригинальные CSS‑переменные восстановятся.  
VERIFY: Открыть `index.html?theme=alt`, убедиться, что основной акцентный цвет изменился (проверить визуально или через `getComputedStyle`), затем выполнить клик‑логгер, сравнив количество кликов с базовым вариантом.  
PRIORITY: 1 – низкая стоимость, потенциально высокий эффект на конверсию и визуальное восприятие.
